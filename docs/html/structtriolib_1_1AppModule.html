Detailed Description

Note
When constructing, parent is nullptr!

There are two independent orderings a mod can influence:

  • The init/quit order: mods init in this order, and quit in the reverse of this order (last to init is first to quit).
  • The loop order: mods loop in this order.

Each ordering has its own before/after/priority hooks so a mod can, for example, insist on looping last while not caring at all about init/quit order (or vice versa).

Rules for the constraints:

  1. A mod cannot claim to go both before AND after the same other mod in the same ordering - that is a contradiction and throws.
  2. If two mods mutually disagree (A wants to go before B, B wants to go before A - via any combination of before/after calls), the mod with the higher priority for that ordering wins. If the priorities are equal, the outcome is unspecified (but deterministic for a given mod list/order).
